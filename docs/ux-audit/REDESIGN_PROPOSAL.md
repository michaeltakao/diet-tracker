### 次の一手ルール (`lib/next-action.ts`, 優先順; すべて JST)
| 順 | 条件 | 表示 |
|---|---|---|
| 1 | 目標未設定 | 目標を設定 → `/onboarding` |
| 2 | 時間帯の食事スロット (朝 <11:00 / 昼 11:00–15:59 / 夕 16:00–) が未記録、またはそれより前の主食スロットが未記録 | 「◯食を記録」→ `/add?meal=…` |
| 3 | 今日の体重が未記録 | 「体重を記録」→ 体重入力へ |
| 4 | 全部済 | 「今日の記録は完了」→ `/log` |

- **連続記録の途切れは表示しない** (意見: 罰を与える表示は離脱を招くという仮説; 文献確認は P1)。
- 朝の体重を食事より優先しない理由 (意見): core loop の主記録は食事 (ADR-011)。体重は 1 行カードで常に見えている。

### 削除しないもの
推薦カード (論文の成果物)、MedWarning、水分記録。

## 3. 食事記録フロー
- 入口: ホームの各スロット「＋」→ `/add?meal=dinner` (スロット固定)。FAB は時間帯推定のまま。
- `/add` 先頭: 「このスロットで前回食べたもの」上位 3 件 (`getRecentFoods` を meal type で絞る) → 1 タップ記録 + Undo トースト。
- 写真: 信頼度 low/medium の時、注意表示 (枠を強調) + 「量を確認してください」。人前チップ (0.5/1/1.5/2) を結果直下に。保存は従来どおりユーザー確定後。**信頼度の DB 保存はしない** (スキーマ変更回避)。
- 昨日コピー: 確認シート (件数・合計 kcal) + 同日 2 回目は「既にコピー済み」で無効化。
- 削除: 即時削除 + 5 秒 Undo トースト。
- 音声入力: P2。

## 4. 運動推薦フロー (P1 設計のみ; ADR-011 により実装しない)
- **決定論層**: 入力 = 環境 (自宅/ジム/外/休養) × 器具 × 経験 × 疲労 (自己申告 1–3) × `getWorkoutWarnings` (疾患・服薬) → `lib/exercise-db.ts` の `pattern` で候補選択・回数/セット上限。安全判定はここだけ。
  - 計算量: 候補 N 件 × 制約 M 件のフィルタ = O(NM)、N≈100 で無視できる。
- **LLM 層**: 選ばれた候補の説明文・代替案だけ。出力は候補 ID 以外を捨てる (`filterRecommendation` と同じ型)。
- 代替案: (a) LLM なしのテンプレート説明 — 安価・決定論だが個別性が低い。(b) LLM に候補生成も任せる — 柔軟だが安全判定を LLM 出力の後段で再実行する必要があり、評価が難しい。
- 着手条件: 参加者の workout 記録が実際にあること (「データが出るまで新機能なし」)。
